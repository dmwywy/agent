## 交互式启动（推荐先跑这一个）

Windows 下**双击仓库根目录的 `run.bat`**（它只是 `python launcher.py` 的薄包装），
或在项目根目录执行 `python launcher.py`。之后按提示逐步操作即可，**全程无需改动任何文件**：

1. **环境自检**：检查 Python 与依赖；缺依赖自动执行 `pip install -r requirements.txt`。
   若本机没有 Python，`.bat` 会提示并打开官方下载页（安装时勾选 “Add Python to PATH”）。
2. **选择运行方式**：`1` 命令行（跑完直接出三端报告）/ `2` 网页（自动打开浏览器界面）。
3. **检查 DeepSeek 配置**：`.env` 中已有 `DEEPSEEK_API_KEY` 时，让你选在线 / 离线；
   没有时让你输入 Key（写入 `.env`；该文件已 gitignore，不会提交），或直接跳过走离线。
   **离线模式不需要网络与 Key**，是评审复现的默认口径。
4. **输入材料文件夹路径**：可混放年报 / 研究报告的 PDF、DOCX，支持多份，**无需文件名约定**
   （按文件内容识别）；**直接回车 = 使用仓库自带 demo 数据**。
5. **运行**：命令行分支复用 `fincheck`（`ingest` / `run` 并自动生成三端报告）；
   网页分支启动 `streamlit run app.py` 并自动打开浏览器。

> **关于 exe**：仓库根已提供 `launcher.exe`（PyInstaller 单文件外壳，约 8.5 MB），它只做
> **「检测环境 → 引导 → 拉起源码」**，核查逻辑仍由旁边的 Python 源码执行；本机没有 Python 时
> 会自动下载官方内嵌运行时到 `.runtime/`，因此免装环境也能跑。之所以不把 Streamlit 应用整体
> 打进去：那样产物体积数百 MB、还需处理静态资源钩子，构建脆弱且对评审没有额外加分。
> 大赛要求提交**完整源代码 + 依赖文件 + 运行说明**，本仓库三者齐备；`run.bat` / `launcher.py` /
> `launcher.exe` 三条入口行为完全一致。需要重新打包：双击 `build_exe.bat`。

## 四、配置 API Key（仅在"在线模式"需要）

模型调用是**受限期**语义任务（科目归一化 / 研报引用匹配 / 异常解释 / 报告定性文字），
在线运行需 DeepSeek API Key；**离线模式只用本地缓存，无需 Key、无需联网**。

```bash
copy .env.example .env        # Windows
# cp .env.example .env        # Linux / macOS
# 编辑 .env，填写：
#   DEEPSEEK_API_KEY=sk-xxxxxxxx
#   MODEL_ID=deepseek-flash
```

网页界面也支持在表单里临时填写 Key（留空则回退读取 `.env`）。密钥仅用于构造请求，
**不写入日志、报告或缓存**。

## 五、运行方式

### 5.1 命令行（CLI）

```bash
# ① 跑已有结构化数据（离线复现，评审推荐）
python -m fincheck run --config configs/demo.yaml --run-id demo_check --offline

# ② 文件夹入口：给一个装着年报/研报的文件夹，按【文件内容】自动识别材料并跑完整流程
python -m fincheck ingest --from "<材料目录>" --run-id study_01

# ③ 只重生成报告（PDF / Excel / 网页）
python -m fincheck report --run-id demo_check --formats pdf,xlsx,html
```

产物全部落在 `runs/<run_id>/`：提取字段、规则结果、CSI、研报引用核查、日志与三端报告。

### 5.2 网页界面（Web）

```bash
streamlit run app.py
```

上传年报 / 研报 → 选择期间与离线开关 → 一键核查并生成报告；页面含「异常清单 / 一致性指标 /
提取字段 / 规则明细 / 报告下载」五个页签，并支持切换历史运行。

### 5.3 MCP 服务（stdio）

本项目提供 **MCP（Model Context Protocol）服务**，把核查能力以标准工具形式暴露给 MCP 客户端，
零新增第三方依赖（标准库实现 stdio JSON-RPC 2.0）：

```bash
python -m mcp_server              # 启动 stdio 服务
python -m mcp_server --selftest   # 离线自检（不发网络请求、不调模型）
```

仓库根 `.mcp.json` 给出客户端接入配置样例。暴露的 **5 个工具**与 **3 个资源**：

| 工具 | 说明 |
|---|---|
| `fincheck_ingest` | 给文件夹按内容识别材料并跑完整流程 |
| `fincheck_run` | 对已有结构化数据跑完整核查流程 |
| `fincheck_report` | 重新生成三端报告 |
| `calculate_ratios` | 确定性财务比率计算（不调模型） |
| `check_consistency` | 一致性规则核查 + CSI 评分（纯确定性） |

| 资源 URI | 内容 |
|---|---|
| `fincheck://runs` | 历史运行编号列表 |
| `fincheck://runs/{run_id}/manifest.json` | 运行清单（提示词哈希、调用统计） |
| `fincheck://runs/{run_id}/rules/csi.json` | CSI 总分与维度明细 |

> MCP 层是既有函数/入口的**薄封装**，产物与 CLI 逐字节一致，不修改任何业务流程代码。

### 5.4 自检与测试

```bash
python -m pytest -q                # 汇总测试
python testcontract.py             # 模型调用方案契约自检
python tools/check_fields.py       # 字段字典与规则库自检
python -m mcp_server --selftest    # MCP 服务自检
```

## 十、限制与声明

1. 本系统输出为**财务数据一致性核查结果**，不构成投资建议，所有结论需人工复核。
2. 语义任务在离线缓存未命中时统一转「待复核」，**不会以模型猜测替代确定性结论**。
3. CSI 为**临时口径**（部分维度不适用时权重会分摊），页面与报告均已显式标注。
4. 未识别的上传文件（未识别 / 处理失败 / 识别到但未抽出内容）在网页端与三端报告中**一律显式列出**。
