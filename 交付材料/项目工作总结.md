# 项目工作总结（交付材料）

> 项目：财报一致性量化核查智能体（金融人工智能大赛 2026）
> 范围：`agent/` 目录内的智能体实现。最终报告书与现场样例数据不在本工作范围内。

---

## 一、目标与定位

以**大语言模型为核心推理引擎**，对上交所上市公司年报与券商研究报告做**财务数据一致性核查**：
程序负责确定性计算与比对，模型只做受限期语义判断（科目归一化、研报引用匹配、异常解释、报告定性文字），
最终以**结构化数据 + 表格 + 分析报告（PDF / Excel / 网页）**形式呈现，全过程可追溯、可复现。

---

## 二、完成的主要工作

### 1. 智能体主流程与核心模块
- 编排框架：`src/pipeline.py::run()`（解析 → 语义 → 规则 → 评分 → 报告）+ CLI `python -m fincheck`。
- Tool（9 脚本）、Prompt（4 提示词）、Skill（9 份 `SKILL.md`）、数据处理、日志记录（JSONL + 运行清单）齐备。
- **补齐 MCP 模块**：`mcp_server/` 以标准库实现 stdio JSON-RPC 2.0 服务，暴露 5 工具 / 3 资源，
  零新增第三方依赖，产物与 CLI 一致。

### 2. C研（研报引用核查）能力
- 确定性规则 RC01~RC05（引用一致性、同比核验、表内自校验、单位口径、研报内一致性）。
- **新增 RC06 大模型语义审计层**：给模型充分的发现空间以识别清单外的潜在问题；
  结论**严格限制为「待人工复核」**，且证据原文须逐字存在于研报中，防止幻觉。
- 关键修复：同一 claim 可同时命中多种错误（排他键由 `claim_id` 改为 `(claim_id, cause)`）；
  金额/百分比枚举分型匹配；同比缺基期时显式标记待复核而非静默跳过。

### 3. 结果可读性与一致性
- 四端（网页 / PDF / Excel / HTML）**异常计数统一口径** `merged_anomaly_counts()`，消除"网页 0 条、报告 3 条"的分裂。
- 每条异常**标注位置**（页码 + 段落 / 表行）。
- 异常说明改写为可读文案并**指名应改成什么**；四端表格新增「**应为（正确值）**」列。
- 未参与核查的上传件（未识别 / 处理失败 / 识别到但未抽出内容）在网页与三端报告中一律显式列出。
- 代码指纹校验 + 过期产物自动重算，避免"改了代码结论没变"被误读。

## 四、遗留项与后续建议

1. **年度审计报告 docx 抽取覆盖不足**：文件已被识别为年报，但抽取不到核心报表科目，
   现已在报告与网页端如实标注为"未参与核查"。后续建议完善 docx 表格抽取以使其真正参与核查。
2. **C研 待人工复核条目偏多**（样例运行 44 条）：离线缓存未命中与缺乏基线（如预测类指标）所致；
   在线运行并将缓存补齐后可显著下降。
3. **CSI 为临时口径**：部分维度不适用时权重会分摊，页面与报告均已显式标注；如需固定口径需进一步约定。
4. **第三方合规**：传递依赖 `pymupdf`（AGPL-3.0）仅存在于可选路径，对外发布前需按 `docs/third_party.md` 复核。
