## 1. 逐项模块映射

### 1.1 智能体编排框架

| 项 | 内容 |
|---|---|
| 《项目思路》要求 | 编排"解析 → 语义 → 规则 → 评分 → 报告"的智能体主流程 |
| 仓库实现 | `src/pipeline.py::run()`（主编排：加载配置→读取结构化数据→科目归一化→研报引用匹配→C研 数值比对→五维规则核查→异常解释→落盘清单）；`fincheck/__main__.py::main()`（CLI 三个子命令 `run` / `ingest` / `report` 与运行摘要） |
| 入口 | `python -m fincheck run --config configs/demo.yaml --run-id <id>`；文件夹入口 `python -m fincheck ingest --from <目录> --run-id <id>`；报告 `python -m fincheck report --run-id <id>` |

## 3. 缺口模块的现状判断与替代方案

### 3.1 Skill 任务能力模块 —— ✅ 已实现（声明式定义）

- **现状**：`skills/` 目录下共 **9** 份 `SKILL.md` 声明式定义：
  - **模型侧任务（5）**：`match_item` / `match_claim` / `explain_anomaly` / `gen_commentary` /
    `audit_claims`（研报语义审计，结论仅落"待人工复核"、证据须逐字核验），
    每份含能力边界、输入输出契约、校验层与代码落点，与 `src/schemas.SCHEMA_BY_TASK` 一一对应。
  - **确定性能力（4）**：`financial-ratio-calculator`（财务比率计算）/
    `consistency-checker`（一致性核查，封装 27 条规则）/ `field-extractor`（字段提取）/
    `report-generator`（报告生成），对应 `src/financial_analysis.py`、`src/rules_engine.py`、
    `tools/extract_fields.py`、`src/report.py`，并各含输入输出 schema。
- **与运行时的关系**：本项目采用的智能体范式是"编排器 + 提示词 + 受限输出 schema"，
  任务能力由 `src/tasks.py::call_task()`（加载提示词 → 调用 → 三层校验 → 修复重试）承载。
  `SKILL.md` 是对这些任务的**声明式封装**，供评审核对"模块存在性"。删除它不影响运行，
  仅代表该 Skill 的"声明"缺失。
- **契约**：能力边界与输入输出已在 `docs/interfaces.md` §5.1/§5.2 冻结，无需改动业务流程代码。

### 3.2 MCP 接口/服务模块 —— ✅ 已实现

- **现状**：`mcp_server/` 下有真实可运行的 MCP 服务：
  - `mcp_server/server.py`：**标准库**实现的 stdio JSON-RPC 2.0 服务，支持
    `initialize` / `notifications/initialized` / `tools/list` / `tools/call` /
    `resources/list` / `resources/read` / `ping`；
  - `mcp_server/__main__.py`：`python -m mcp_server`（stdio 服务）与
    `python -m mcp_server --selftest`（离线自检）入口；
  - 仓库根 `.mcp.json`：MCP 客户端接入配置样例。
- **工具（5）**：`fincheck_ingest` / `fincheck_run` / `fincheck_report` / `calculate_ratios` /
  `check_consistency`，逐一薄封装 `src/` 既有函数（`src.ingest.ingest`、`src.pipeline.run`、
  `src.report.build_all`、`src.financial_analysis.analyze`、`src.rules_engine.run_rules`）。
- **资源（3）**：`fincheck://runs`、`fincheck://runs/{run_id}/manifest.json`、
  `fincheck://runs/{run_id}/rules/csi.json`。
- **性质**：薄封装、**零侵入**——不修改任何业务流程代码；产物与 CLI 逐字节一致。
- **零依赖**：仅用标准库，**不新增 `requirements.txt` 条目**（评审无需安装 `mcp` SDK）；
  目录名用 `mcp_server/` 而非 `mcp/`，避免同名本地包遮蔽已安装的官方 SDK。
- **其他运行入口（仍然保留）**：
  1. **命令行（CLI）**：`python -m fincheck {run,ingest,report}`（`fincheck/__main__.py`）；
  2. **网页服务**：`app.py` + `src/web.py::run_uploaded_reports()`，`streamlit run app.py`；
  3. **对外模型通道**：`src/llm.py::call()` 是全项目唯一出站入口（`https://api.deepseek.com`）。

> 结论重申：**Skill 模块有 9 份声明式 `SKILL.md`（`skills/`，5 模型任务 + 4 确定性能力）；
> MCP 模块已以 `mcp_server/` 真实落地（5 工具 3 资源，标准库实现，零新增依赖）。**
> 决赛材料中可直接将 MCP 标注为**已实现**。
