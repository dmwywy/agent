### 1.1 智能体编排框架

| 项 | 内容 |
|---|---|
| 《项目思路》要求 | 编排"解析 → 语义 → 规则 → 评分 → 报告"的智能体主流程 |
| 仓库实现 | `src/pipeline.py::run()`（主编排：加载配置→读取结构化数据→科目归一化→研报引用匹配→C研 数值比对→五维规则核查→异常解释→落盘清单）；`fincheck/__main__.py::main()`（CLI 三个子命令 `run` / `ingest` / `report` 与运行摘要） |
| 入口 | `python -m fincheck run --config configs/demo.yaml --run-id <id>`；文件夹入口 `python -m fincheck ingest --from <目录> --run-id <id>`；报告 `python -m fincheck report --run-id <id>` |

## 3. 缺口模块的现状判断与替代方案

### 3.1 Skill 任务能力模块 —— ⚠️ 缺口

- **现状**：仓库内**没有**任何 Skill 定义文件（如 `SKILL.md`）、Skill 注册表或 Skill 调度代码。
  全仓库仅在 `docs/AI接续执行手册_20261012.md` 第 124 行出现过一次 "skill" 字样，
  且指的是**外部 AI 工具环境自带的 PDF/Spreadsheet 渲染能力**（用于人工核验报告版式），
  **不是本仓库实现的模块**。据此判断：Skill 模块**未实现**。
- **为什么不算"已实现"**：本项目采用的智能体范式是"编排器 + 提示词 + 受限输出 schema"，
  任务能力由 `src/tasks.py::call_task()`（加载提示词 → 调用 → 三层校验 → 修复重试）承载，
  这是**任务级接口**，不构成平台意义上的 Skill 组件；把它写成"已实现 Skill"属于概念套用。
- **替代方案（已在仓库内可运行）**：
  1. 用 `src/tasks.py` 的 5 个受注册任务（`SCHEMA_BY_TASK`：`match_item` / `unit_period` /
     `match_claim` / `explain_anomaly` / `gen_report_text`）作为"能力清单"，
     每个任务 = 一份 `prompts/<task>.txt` + 一个 `pydantic` 输出 schema；
  2. 若比赛现场要求展示 Skill 形态，可据此在**平台侧**将上述任务各包装为一个 Skill，
     能力边界与输入输出已在 `docs/interfaces.md` §5.1/§5.2 冻结，无需改动业务流程代码。

### 3.2 MCP 接口/服务模块 —— ⚠️ 缺口

- **现状**：仓库内**没有**任何 MCP（Model Context Protocol）server 或 client 实现：
  无 MCP 依赖、无 `mcp` 相关代码、无 `.mcp.json`/server 声明（全仓库 grep 无 "MCP" 命中）。
  据此判断：MCP 模块**未实现**。
- **替代方案（本仓库实际对外接口）**：
  1. **命令行接口（CLI）**：`python -m fincheck {run,ingest,report}`，参数与行为见
     `fincheck/__main__.py`，即"服务"的最小可用形态；
  2. **网页服务**：`app.py` + `src/web.py::run_uploaded_reports()`，`streamlit run app.py`
     在 `127.0.0.1` 提供上传核查与结果查看（`src/netguard.py` 放行本机回环）；
  3. **对外模型通道**：`src/llm.py::call()` 是全项目唯一出站入口，走 OpenAI 兼容 HTTP
     （`https://api.deepseek.com/chat/completions`），可视为"模型服务"接入点。
  若决赛需要 MCP，可在**不修改业务流程代码**的前提下，将上述 CLI/网页入口按 MCP
  协议封装为 tool server（输入输出沿用 `docs/interfaces.md` 的 JSON 契约）。

> 结论重申：**Skill 与 MCP 两个模块在本仓库中均无对应实现，属缺口；**
> 决赛材料中如提及这两个模块，应如实标注"未实现（规划/替代方案见上）"，
> 不得写为已完成。
