## 一、项目是什么

**2026 北京市大学生金融人工智能竞赛**参赛作品，主题「金融投研智能体构建」。

作品名：**面向上市公司定期报告的财务报告信息一致性量化核查与研究报告纠错智能体**

技术路线（《项目思路》原话）：**"程序负责计算、模型负责理解"**
- 程序：解析、单位换算、金额校验、规则比对、指数计算——所有数值结论由程序产生

缺省 = 同一 `(period, period_type)` 内取数；`cross_period` = 同一时点期末 vs 下一年报期初

## 五、★ 关键设计决策（含理由，别改回去）

### 1. `thinking` 必须关闭（最重要）
`deepseek-flash` **默认开启深度思考**，`reasoning_content` 与正文**共享 `max_tokens`**。
实测同一批输入：`enabled` 烧光 8000 token 返回**空正文**；`disabled` 只用 242 token。
差 33 倍，且默认档位会让契约直接失败。写在 `src/llm.py` 的 `THINKING`。

### 2. 推理参数必须全进缓存键
`PARAMS` 里含 `temperature/top_p/max_tokens`，`THINKING` 也参与。
否则改了参数缓存却不失效，会命中旧结果，"可复现"失真。

### 3. 模型不产出数值、不产出位置
- `match_item` / `match_claim` 的 `evidence` 由**程序确定性回填**（一批 40 条，单个 evidence 覆盖不了）
- 异常归因由程序做（是否 10 的整数次幂、是否符号相反），模型只在候选中选并措辞

### 4. 模型措辞不写进结果文件
`results.json` / `csi.json` 必须逐字节可复现。模型解释只写 `explanations.json`，
报告与网页按 `rule_id`/`claim_id` 关联展示。

### 5. 期间不许混
- 资产负债表项目 = 时点（`BAL_END`/`BAL_BEG`），利润表/现金流量表 = 时期（`FY`）
- 附注各小节期间性质不同：货币资金是期末/期初余额（时点），补充资料是本/上期金额（时期）
- 单季数与年度累计不可比（C研 里判 `REVIEW` 而非 `FAIL`）

### 6. 字段缺失判 NA，不判 FAIL
`NA` 不计入分母。"没数据"不能报成"有问题"。

### 7. 报告只呈现，不重算
改规则必须重跑流程；只跑 `report` 不会更新结论。

### 8. 数据隔离
现场解析写 `runs/<run_id>/ingested/`，**不写**共享 `data/`。
`load_structured` 会把目录下所有 json 读进来，堆两批就串数据。

### 9. 时点数与时期数不许直接相加，要按「报告年度」对齐
权益变动表的勾稽要同时用三种期间：未分配利润**期末**（2024-12-31 时点）、
**期初**（2023-12-31 时点）、本年**净利润与利润分配**（FY 2024 时期）。
引擎默认按 `(period, period_type)` 分组取数，会把它们拆进三个组、每组都缺字段而误判 NA。
故引入规则的第三种取值方式 `kind: report_year`：期初记录归属**下一年度**的报告期
（`_report_year()`），三种期间按报告年度合到一期再代入表达式。`fields.yaml` 的 `period`
决定每个字段该取哪一类记录。**新增这类跨期间勾稽时，先想清楚归属年度。**

### 10. 空白行 ≠ 未披露（仅限固定模板表）
现金流量表补充资料是准则规定的**固定模板**，逐行印出全部调节项，空白行表示
"本年无此项金额"（=0），与"未披露"不同。所以 CF02 用 `zero_if_absent` 列出调节项：
取到值就用真实值，没取到按 0 计；`requires` 里的锚点（净利润、经营净额）缺一仍判 NA。
**这个口子只对显式列出的字段开**，不得当成"缺字段就填 0"的通用做法。

### 11. 规则表不能照抄，要按披露口径改写（否则必然误报）
- 规则表第 13 条"利润表净利润 = 权益变动表综合收益总额 − 其他综合收益"：该式只在
  **少数股东其他综合收益为 0** 时才等于合并净利润。改为取"综合收益总额行的未分配利润列"
  （即归母净利润）与利润表归母净利润比 —— 恒等成立，LJ03。
- 规则表第 18 条口径下的"盈余公积期末 = 期初 + 提取盈余公积"**未转录**：2025 年茅台的
  盈余公积还在"（二）所有者投入和减少资本"里被调减 46.23 亿，照抄会误报。已在
  `rules.yaml` 注释里写明为何不转录，避免后人"补全"回去。
- 分部小计**不等于**利润表营业收入（差 2.87 亿其他业务收入），IS04/IS06/IS07 只做
  分部表内部加总，不跨表比营业收入。

## 六、★ 踩过的坑（同样的问题别再犯）

| 坑 | 现象 | 修法 |
|---|---|---|
| **netguard 拦回环** | 装上后 `127.0.0.1` 被挡，**网页界面直接崩** | 放行 `127.0.0.1/::1/localhost`；补 `uninstall_allowlist()` 供测试还原 |
| **CSI 漏算 C研** | 查出 2 条研报错误，CSI 仍显示 100 分**虚高** | `run_rules` 读 `research_claims.json` 并入 CSI |
| **畸形单位漏检** | "862.3 **亿万元**"数值凑巧在容差内被判 PASS | 单位写法非法单判 `UNIT_SCALE`，数值接近也不放行 |
| **畸形单位崩溃** | 量级字表有 `"千元"` 无 `"千"`，`KeyError` 打断全流程 | 补 `"千"` 并改 `.get` 兜底；单条异常只丢该条 |
| **分部营收误挂总营收** | "茅台酒…**营收** 1495.3 亿"被当成总营收 | 金额按**最近前置指标名**归属；泛化别名（"营收"）移出匹配表 |
| **单季 vs 全年** | "2024Q4 营收 510.2 亿"拿去比年报 1741 亿 → 误报 | 句中带 Q1–Q4/半年 且记录是 FY → 判 `REVIEW` |
| **一条 claim 只返回一个科目** | 句中第二个指标的错误被漏掉 | 提示词要求**每个指标各输出一条 match** |
| **docx 附注标题** | 2024 写 `1、货币资金`，2025 写 `8. 货币资金` | 正则同时接受全角顿号与半角句点 |
| **年报标题错字** | 原件把"现金流量表补充资料"写成"**金**流量表补充资料" | 小节匹配用「包含」而非「相等」 |
| **docx 无固定分页** | 硬编页码等于伪造证据 | 用 `locator`（章节/表号/行号）替代 `page`（`interfaces.md §1.3`） |
| **CLI 静默** | 跑完无输出，使用者以为失败 | `fincheck` 打印运行摘要 |
| **manifest.calls 恒为 0** | README 承诺统计调用次数，字段建了没人写 | 落盘前从 `logs.jsonl` 回算，按 `started_at` 过滤 |
| **pyarrow 列类型** | 网页"得分"列混数字与"不适用" → `ArrowInvalid` | 统一转字符串 |
| **离线指数级拆分** | 缓存未命中触发二分递归，77 次调用 | 只有 `OUTPUT_EMPTY` 才拆分 |
| **测试污染全局** | `install_allowlist` 改写 socket 且不还原，后续测试全挂 | 用 `try/finally` 还原 |
| **权益变动表被拆成多个表格对象** | "四、本期期末余额"落在**续表**里，续表没有年份表头 → 最关键的期末数整行丢失 | 年度跨表传递：见到新表头才换年度，见不到就沿用上一张（`_scan_equity_table` 的 `eq_year` 入参） |
| **合并表头与数据行列数对不上** | 列头是纵向合并单元格，解析出来只有 14 格、数据行 16 格，按表头对列号会取错列 | 权益变动表按数据行**列序号**硬定位，并**强制校验列数**——不符就整表跳过，宁可 NA 不可取错 |
| **行标签被跨页拆成两行** | 2025 年报把"归属于母公司所有者权益"与"（或股东权益）合计"分成两行，金额留在前半行 → EQUITY_PARENT 整条丢失，BS02/LJ05 误判 NA | 补别名"归属于母公司所有者权益"（`LABEL_ALIASES`） |
| **科目名超过单次调用上限** | 规则库扩容后一份年报的科目名 > 40 个，`build_match_item` 的断言直接把整条流程打断 | `run_match_item` 按 `MAX_ITEMS` 分批（与研报 claim 分批同构） |
| **检查器与契约不一致** | `check_fields.py` 校验 `period_type`，而 `interfaces.md §7.1` 与 `fields.yaml` 用的是 `period` → 36 个字段全报"不合法" | 改检查器对齐契约，**不改真源** |
| **同名行在不同小节含义不同** | 分部表里"酒类"在分行业/分产品小节都有；"合计"行在应收账款与**其他应收款**附注里结构完全相同 | 抽取一律先锁"小节 + 子小节"再取行/列，不锁小节就会串数 |
| **小节标题被当成数据行** | 补充资料表"1．将净利润调节为经营活动现金流量："也含"净利润"，被匹配成净利润行 | 以冒号结尾的行按小节标题拒掉（`_match_note_item`） |
| **零异常的运行反而崩掉** | 一条 FAIL/REVIEW 都没有时 `explain_anomalies` 不落 `explanations.json`，`pipeline` 却无条件读它 → `FileNotFoundError`。**越干净的输入越走不通** | 抽 `explain_summary()` 容忍缺文件，返回"无异常，无需解释" |
| **mock 工具没跟着分批** | `make_mock.py` 自称"复现 pipeline 的分批"，`match_item` 却仍一次性全发 → 科目名超 40 直接断言失败 | 同步按 `MAX_ITEMS` 分批 |
