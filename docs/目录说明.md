## 一、顶层文件（双击或直接执行的入口）

| 名称 | 作用 |
|---|---|
| `run.bat` | **双击入口**（薄包装）：检查本机 Python，然后调用 `launcher.py` |
| `fincheck-launcher.exe` | 同上，但**免装 Python**：找不到解释器时自动下载官方内嵌运行时到 `.runtime/` |
| `launcher.py` | **交互式启动器本体**：环境自检/自动装依赖 → 命令行或网页 → DeepSeek Key → 材料文件夹 → 运行 |
| `app.py` | **网页界面入口**（`streamlit run app.py`） |
| `build_exe.bat` | 重新打包 `fincheck-launcher.exe`（PyInstaller，仅构建时使用） |
| `README.md` | 运行说明主文档 |
| `requirements.txt` | 依赖清单（评审按此 `pip install`） |
| `.env.example` | API Key 配置模板；实际使用复制为 `.env` 并填写 |
| `.mcp.json` | MCP 客户端接入配置样例（指向 `mcp_server/`） |
| `.gitignore` | 忽略 `.env`、`.venv/`、缓存、构建产物 |
| `.vscode/settings.json` | 编辑器配置（不影响运行） |

## 二、`src/` —— 智能体编排框架与核心引擎

| 文件 | 作用 |
|---|---|
| `pipeline.py` | **总编排**：解析数据 → 语义提取 → 规则核查 → 量化评分 → 报告 |
| `tasks.py` | 任务级接口：加载提示词 → 调用闸门 → schema 校验 → 失败修复重试 |
| `llm.py` | **模型调用闸门**：全项目唯一出站入口（凭据、缓存、重试、JSON 强制、调用记录） |
| `inputs.py` | 把解析结果包装成模型输入（只做包装，不做数值计算） |
| `ingest.py` | **文件夹入口**：给一个文件夹，按**文件内容**识别材料并跑完整条流程 |
| `web.py` | Web 上传编排（Streamlit 表单与本地验收共用） |
| `schemas.py` | 各任务输出的结构定义 |
| `validators.py` | 输出校验：数值白名单、证据原文逐字校验 |
| `rules_engine.py` | **规则核查引擎**：表内勾稽 / 跨期衔接 / 表间一致 / 主表附注 + CSI 评分 |
| `research_check.py` | **C研 维度**：研报引用核查的确定性计算部分（RC01–RC05） |
| `semantic_audit.py` | **C研 语义审计层**（RC06）：交给大模型指出确定性规则覆盖不到的语义问题，结论只落「待人工复核」 |
| `financial_analysis.py` | 确定性财务分析（程序算数、模型不参与、结果可复现） |
| `derived.py` | 确定性派生计算（程序算数、模型写话） |
| `forecast.py` | 盈利预测基础模块（分产品收入预测 + PE 估值情景测算） |
| `explain.py` | 异常原因解释：程序查出的不一致交模型做「选择题」，再由程序校验 |
| `report.py` | **报告生成**：PDF / Excel / 网页三端，含异常表「应为（正确值）」列 |
| `manifest.py` | 运行清单：模型、参数、提示词哈希、输入哈希、调用统计（不含密钥与正文） |
| `logger.py` | 统一的 JSONL 事件日志（一行一事件，便于机器比对与追溯） |
| `netguard.py` | 联网边界：只允许白名单地址，其余拦截并记录 |
| `codefingerprint.py` | 代码指纹：判断某次运行的产物是否由**当前**源码产出 |
| `refresh.py` | 产物新鲜度：代码改动后自动重算**确定性**产物 |
| `errors.py` | 错误分类与提示（不依赖其他项目模块） |
| `__init__.py` | 包标识 |

## 三、`prompts/`（提示词）· `skills/`（任务能力）· `rules/`（规则与字段）

| 位置 | 作用 |
|---|---|
| `prompts/match_item.txt` | 模型任务：科目归一化（别名 → 标准字段） |
| `prompts/match_claim.txt` | 模型任务：研报引用匹配（研报句子 ↔ 财报字段） |
| `prompts/explain_anomaly.txt` | 模型任务：异常原因解释 |
| `prompts/gen_commentary.txt` | 模型任务：报告定性文字（核心观点 / 收入 / 盈利 / 现金流 / 风险五节） |
| `prompts/audit_claims.txt` | 模型任务：语义审计（发现清单外的语义型问题） |
| `skills/<任务名>/SKILL.md` | 9 份声明式 Skill：上表 5 个模型任务 + 4 个确定性能力（字段抽取、比率计算、一致性核查、报告生成），说明各自输入输出、调用规则与禁止项 |
| `rules/fields.yaml` | **字段字典真源**：字段名、别名、期间类型、取数位置 |
| `rules/rules.yaml` | 规则库：每条核查规则的字段需求、容差档位与出处 |
| `rules/tolerance.yaml` | 容差档位定义 |

## 九、`runs/<run_id>/` —— 每跑一次的产物（可追溯、可复现）

每执行一次（CLI 或网页）都会新建 `runs/<run_id>/`，目录结构与含义如下：

| 名称 | 含义 |
|---|---|
| `uploaded/` | 上传/输入的**原始文件**（PDF、DOCX 原样存一份，便于追溯） |
| `ingested/` | **解析产物**：从原始文件抽出的结构化字段（每份材料一个 JSON）；研报句子级 claims 在 `ingested/claims/report_claims.json` |
| `llm/` | **模型任务结果**：`mappings.json`（科目归一化）、`claim_matches.json`（研报引用匹配）、`explanations.json`（异常解释） |
| `llm_cache/` | **语义任务缓存**（按输入哈希存模型返回）：离线模式直接读这里，不联网（`离线复现` 的默认口径） |
| `rules/` | **核查结果**：`results.json`（规则逐条结果）、`research_claims.json`（C研 比对）、`csi.json`（CSI 总分与维度明细） |
| `code_fingerprint.json` | 本次运行所用代码的指纹，用于判断产物是否落后于当前代码 |
| `ingest_log.json` | 材料识别日志：每个文件被识别成什么类型、执行了什么动作 |
| `logs.jsonl` | 事件日志：一行一事件（工具调用、模型调用、重试、联网拦截等） |
| `manifest.json` | 运行清单：模型/参数/提示词哈希/输入哈希/调用统计（`api_ok`、`cache_hit`、`cache_miss`、`failed`） |
| `report.pdf` / `report.xlsx` / `report.html` | 本次生成的三端核查报告（网页端展示的是同一份数据的在线版本） |

数据流一句话：

    uploaded/ →（解析）→ ingested/ →（模型语义任务）→ llm/ + llm_cache/ →（规则核查）→ rules/ →（渲染）→ report.*

全过程留痕在 `logs.jsonl`、`ingest_log.json`、`manifest.json`，因此每条结论都能回溯到来源文件与页码。

`runs/demo_baseline/` 是仓库自带的**公共基准产物**（离线演示与比对用），已随仓库提交；其余 `runs/<run_id>/` 为本地运行产物，不入库。

## 十、哪些可以删、哪些不能删

| 类型 | 说明 |
|---|---|
| 可安全删除 | `runs/<run_id>/`（除 `demo_baseline`）、`build/`、`.runtime/`、`__pycache__/`、`.pytest_cache/`，均为可再生成的产物 |
| 需保留 | `src/` `tools/` `rules/` `prompts/` `skills/` `configs/` `data/` `docs/` `交付材料/` 与三个入口（CLI / Web / MCP）——缺任一项会导致功能或交付不完整 |
| 需自行创建 | `.env`（复制 `.env.example` 后填写 Key；该文件已被 gitignore，不会提交） |
