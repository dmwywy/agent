## 0. 这份文档是干什么的

比赛技术要求明确：**"不得将第三方成果冒充为自主开发成果"**，作品须"同步提交与现场展示版本一致的完整源代码"，
并且要"完整记录文件访问、工具调用、计算过程和结果生成情况"。

在实际推进中，信息工程成员借助 AI 助手，**代建了原本属于其他成员分工范围内的部分交付物**。
为避免两件事发生，特写此文档：

1. **团队内部职责混淆** —— 计划书/视频里写的"某成员完成了 X"，与实际不符；
2. **评审质疑成果来源** —— 被问到"这部分是谁做的、怎么做的"时答不上来。

本文档逐条说明：**哪些是代建的、原责任人是谁、做到什么程度、验证到什么程度、还剩什么必须由本人完成。**

**图例**

| 标记 | 含义 |
|---|---|
| 【已验证】 | 有独立来源交叉核对通过，可直接使用 |
| 【可运行】 | 代码跑通、产出符合接口契约，但业务正确性未经人工核对 |
| 【骨架】 | 只留了接口与钩子，核心逻辑未实现 |
| 【待人工】 | 必须由对应成员用专业判断完成，AI 不宜代劳 |

## 2. 代建：成员三（数字经济A）—— 财报数据处理与结构化提取

### 2.1 代建了什么

**（1）解析程序 `tools/extract_fields.py`**
按 `docs/interfaces.md §2.1` 输出字段记录，每条含证据三要素 `page` / `chunk_id` / `raw_text`。
关键设计（均对应文档中的硬性要求）：

- 表格行列归属与数值**由程序确定性抽取，不调用任何模型**（`§5.3` 禁则2）；
- 只在**合并口径**的主表内取数，遇到"母公司资产负债表"等标题即切断（`§1.5` 口径不许混）；
- 时点数区分期末/期初：`BAL_END` / `BAL_BEG`（`§1.5` 期间不许混）；
- 找不到的字段不写入，**不用 `null` 或 `0` 表示未披露**（`§2.1(3)`）。

程序处理了三类真实的 PDF 排版障碍：
① 长科目名折行（`所有者权益（或股东权` / 数字 / `益）合计`）；
② 科目名层级前缀（`一、营业总收入`、`其中：营业收入`、`减：所得税费用`）；
③ 附注式后缀（`营业利润（亏损以"－"号填列）`）。

**（2）结构化数据**

| 文件 | 内容 |
|---|---|
| `data/structured/贵州茅台_2024.json` | 22 个核心科目 × 2024/2023 两期 = **44 条** |
| `data/structured/贵州茅台_2025.json` | 21 个科目 × 2025/2024 两期 = **42 条**（缺 `EQUITY_PARENT`） |
| `data/structured/chunk_index.json` | `chunk_id → {page, source, chars}` 映射表（`§2.3` 必需配套文件） |

### 3.1 规则表行 20 疑似口径混用 ⚠️

### 3.2 CSI 维度口径冲突：`C文` 还是 `C附`？ ⚠️

## 4. 代建：成员二（李思婕）—— 仅做材料盘点，未代写

### 4.0 代建：研报 claim 抽取工具

`tools/extract_claims.py`（10/03 追加）：把模拟研报 docx 切成**句子级 claim**
（正文句子 + 财务表格行），供 `match_claim` 任务使用。产出 `data/demo/研报claims_*.json`。

它只做机械切分与定位（切句、抽句中的数字、标记章节），**不判断对错**，也不属于原定交付物的替代——
即 §4.4 要求的"错误清单 CSV"仍需成员二按约定列格式产出，本工具只是把"从 docx 里取句子"这一步自动化。

三份研报的抽取结果：2024 年 39 条、2025 年 42 条、2026 上半年 35 条。

### 4.1 盘点到的事实

`金融人工智能相关内容/` 下材料**已齐全**：

- 案例材料包：2024/2025 年报（PDF+DOCX）、2026 半年报、三期财务报表附注、三期审计报告
- **模拟研究报告** 3 份（2024 全年 / 2025 全年 / 2026 上半年，用于测试）
- **标准答案清单** 3 份（`2024年模拟研究报告标准答案清单.docx` 等）
- 公开研报 3 份（国信证券 2024/2025 年报点评、2026 中报点评）——放在 `研究报告/` 目录

### 4.2 校对发现：错误数量不达标 ⚠️

我解析了 3 份标准答案清单，实际内容如下：

| 标准答案清单 | 错误条数 | 类型分布 |
|---|---|---|
| 2024 年 | **5** | 单位1 / 期间1 / 数据引用1 / 同比方向1 / 计算1 |
| 2025 年 | **5** | 同上 |
| 2026 上半年 | **5** | 同上 |

每份文档的条目结构为：`错误N：<类型>` / `位置` / `原研报内容` / `修改为（错误内容）` / `修改建议`。

**问题**：`interfaces.md §6.2(2)` 与《项目思路》第六步均要求 **"每类错误至少 2 处，总计 8–10 处"**，
当前每类只有 1 处、总计 5 处，**未达到自己定的验收标准**。若按此计算识别准确率与漏报率，分母偏小、指标不稳健。

### 4.3 校对发现：错误类型枚举三方不一致 ⚠️

| 出处 | 五类取值 |
|---|---|
| `interfaces.md §5.4`（冻结候选） | `UNIT_SCALE` / `PERIOD_MISMATCH` / `SCOPE_MIXED` / `VALUE_ERROR` / `SIGN_ERROR` |
| 《项目思路》第五步（五） | 单位 / 年份或期间 / 数值引用 / 正负号 / 计算结果 |
| **标准答案清单（实际交付物）** | 单位 / 期间 / 数据引用 / **同比方向** / **计算** |

`§6.2(1)` 规定"错误类型从 5.4 的候选中选取"，但实际交付物里的**"同比方向错误""计算错误"不在冻结候选内**，
而冻结候选里的 `SCOPE_MIXED`（口径混用）在交付物中没有出现。

**建议**：由信息工程与成员二共同对齐——是将 `§5.4` 候选扩充为 6 类（增加 `CALC_ERROR`、
把"同比方向"归入 `SIGN_ERROR`），还是调整交付物的类型划分。这直接影响 `explain_anomaly` 任务的枚举白名单校验。

### 4.4 仍需本人完成 【待人工】

1. **错误清单转 CSV**：`§6.2` 要求列固定为 `claim_id / 错误句 / 错误类型 / 标准答案 / 证据应在页码 / 备注`，
   需把 DOCX 转为该格式，并按 §4.2 补足错误数量。
2. **研报首页与页眉声明**：必须标注"本材料为竞赛模拟样例，非任何机构发布的研究报告"（`§6.2(3)`）。
   3 份模拟研报的**文件名**已含"用于测试"字样，但**正文声明是否到位我未逐份核对**。
3. **计划书与视频文案**：完全未代建，属本人核心职责。
